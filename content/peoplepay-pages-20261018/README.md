# Статья People Pay для ne-prosto.ru

Статус: подготовлено к публикации, 18 октября 2026. На боевом сайте изменений нет, ресурс MODX не создан. Оригинал на VPS: sites/ne-prosto/content/peoplepay-pages-20261018/.

## Что подготовлено

- Раздел «Годнота», parent=2, template=8. Автор Антон Ветров.
- Планируемый URL: https://ne-prosto.ru/blog/peoplepay-kakie-stranicy-prinosyat-obrashcheniya . До публикации этот URL не является ссылкой на готовую статью.
- payload.json — поля MODX и TV. published=0 — безопасный черновик. Дата публикации не выдумана: выставляется в момент согласованного выпуска.
- content.html — HTML без повторного H1. Пять figure с alt/подписями, responsive WebP, ссылки на оригиналы PNG. Таблица с локальной прокруткой.
- preview/images/godnota/peoplepay-pages-20261018/ — 22 статических файла (около 1.87 МБ): пять PNG, responsive WebP, обложка WebP, JPG для соцсетей, scoped article.css. Публичный prefix /images/godnota/peoplepay-pages-20261018/.
- assets-manifest.json — точные пути, размеры, SHA256.
- preview/index.html — статический предпросмотр в актуальной оболочке статьи сайта; robots noindex/nofollow. CSS и шрифты при QA шли через read-only proxy production.
- qa.json и desktop/mobile*.png — результаты и визуальные проверки. Статический предпросмотр не подменяет проверку живого MODX после выпуска.

Первичные цифры и factcheck остаются в clients/peoplepay/content/articles/2026-10-18-pages-and-enquiries/. Публикационная сборка сохраняет различие между автоцелью и реальной заявкой CRM. В пакет выпуска не включаются токены, доступы, сырые цели или другие внутренние данные.

## Порядок выпуска после команды Антона

1. Повторно проверить актуальный origin/main и отсутствие занятого uri/alias в CMS. Не запускать исторический design/build_cms.py и не применять общий cms-manifest ради этой статьи.
2. Через штатный одноразовый office1080 runner и GitHub Actions: снять backup только задействованных ресурсов/TV и список существующих файлов; загрузить whitelist из assets-manifest с проверкой SHA. Прямой ручной FTP-деплой в обход CI не использовать.
3. Создать отдельный ресурс из payload, пока published=0. Передать tvs через API MODX, а не как неизвестные колонки modResource. Не перезаписывать существующую статью при совпадении URL. TV page__image--big намеренно пустой: обложка идёт в карточку и OG, внутри статьи первым изображением служит график.
4. Проверить сохранённые поля, SHA content, template/parent, все TV и будущий URI. Только на согласованном выпуске установить published=1 и фактические publishedon/createdon по политике CMS.
5. Обновить кэш и последовательно прогреть статью, /blog/ и главную. Проверить один H1, title/description/OG, дату/автора, 5 иллюстраций, responsive srcset и оригиналы PNG, CTA, отсутствие лишней обложки, mobile/desktop, карточку в «Годноте» и sitemap. Шаблон 8 не меняется этим пакетом; canonical надо проверять в фактическом head, не считать его из статического preview гарантией CMS.
6. Сохранить результаты и worklog, закрыть временные endpoints/runner. При откате снять с публикации только новый ресурс и убрать из выдачи; не трогать чужие записи. Секреты только серверно или GitHub Secrets.
